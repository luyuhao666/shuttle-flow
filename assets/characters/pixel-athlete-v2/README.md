# Shuttle Flow 简洁 3D 运动员 · 游戏与动作预览 v0.3.1

根据用户提供的正面、侧面、背面参考图制作的程序化 3D 外观原型。保留棕色短发、橙色头带、蓝色球衣、前侧浅蓝条纹、背面 7 号、深色短裤、左臂护具、右手橙色护腕、右膝护具、条纹白袜与橙白球鞋。形体和细节经过低模简化，仍需用户确认实际观感。

## 查看

双击项目根目录的 `查看像素角色.lnk`，或本目录的 `preview.html`。也可运行 `npm run preview:pixel-athlete`。默认采用用户选定的“清晰查看模型”效果，开启抗锯齿并适配屏幕像素密度；像素显示仍可选。打开即播放弓腰候球，右侧可切换九组动作，暂停、0.25 / 0.5 倍慢放、循环、逐帧和拖动进度；“静态外观”返回建模姿态。支持正侧背与斜侧视角、面部近景、拖动旋转、缩放、自动旋转、球拍/骨骼显示、保存 GLB。点击“球场效果”查看现有球场中的外观比较截图，点击“返回模型”继续查看动作。更新后关闭旧预览窗口再重新打开。

`preview.html`、`preview.js` 与 `court-preview.png` 一起保留即可离线查看。`athlete.glb` 可单独导入支持 glTF 的软件；用户参考图留存于上一级的 `pixel-athlete-reference.png`。

## 当前范围

- 真正的 GLB 网格、蒙皮与 29 骨骼：全模型 15777 个三角面，其中身体 14129 个，含九段新动作的 GLB 约 3.55 MiB。沿用当前骨骼命名和关节位置，静态身体鞋底与最高点保持原来的 .035 / 1.93116665 米；没有整体缩矮人物。动作的支撑脚鞋底约 .002 米，候球降低重心来自屈膝与脊柱前倾。
- v0.2 根据用户反馈重做面部：平滑脸颊/下颌、贴合脸面的眼白与眼睑、立体瞳孔/高光、眉毛、鼻梁/鼻尖和嘴形；移除旧圆球肩部，改为下倾肩袖轮廓，并修正衣摆、袖口与袜子交叠接缝。手臂/腿部加粗、手掌放大，鞋子加宽加长，护具与短裤同步适配。
- 球拍是挂在 `RightHand` 下的独立 `BadmintonRacket` 部件，沿用现有球拍。`RacketContact` 标记拍面中心，后续可单独替换球拍网格，保留握柄与拍面定位约定。
- v0.3 替换旧兼容动作，新增九段为当前网格编写的动作。候球持拍手在胸前，双肘收低并配合轻微呼吸；并步先迈领脚再跟进，换向前有重心预压，两脚不交叉；起跳包含下蹲、蹬地、抬脚收腿、伸腿落地与屈膝缓冲；正手/跳杀含侧身引拍、较快的头顶伸展挥拍与较慢收拍；反手沿胸前路径避让当前更粗的手臂；v0.3.1 纠正拍头向反手侧前方挥出，随挥和收拍时拍杆保持在身前，减少回收时插入躯干；补充跨步和低手发球。调整腰侧被衣物覆盖的大腿蒙皮，减少屈膝时从裤腰露肤。
- 已替换进正式游戏：玩家蓝色球衣，人机米色球衣。开发入口、离线网页、本地 HTTP 和重建的 Windows 程序均使用本模型。场地、相机、UI、操作、移动物理和击球/杀球判定沿用现有游戏；待发球左键高远、右键小球保留。旧角色资源留存以供比较。
- 默认使用清晰显示，球场比较沿用现有高清角色适配层，不再强制角色像素化。独立预览的像素显示选项仅供比较，场地和 UI 的高清渲染保留。模型保留分块色彩、简洁轮廓与几何数字细节，没有外部贴图。
- 游戏个性化支持玩家/人机各自的球衣主色与条纹颜色，自动条纹搭配和浅色球衣号码加深；保留领袖白边与形状。球衣与袜子、短裤不再共用可换色材质：`Athlete_Jersey` 为衣身和袖子，`Athlete_Stripe` 为前条纹/胸徽强调色，`Athlete_JerseyNumber` 为背号；袜子/短裤装饰分别为 `Athlete_SockStripe` / `Athlete_ShortsStripe`。仅分离材质，顶点形状、三角面总数、骨骼与九段动作不变，GLB 为 3721748 字节。运行时两位角色各自克隆材质，换色不会改写源 GLB，独立预览仍用原配色。

## 重建与检查

```powershell
npm run build:pixel-athlete
npm run verify:pixel-athlete
npm run pixel-athlete:shortcut
```

建模源文件：`scripts/lib/pixel-athlete-model.mjs`，动作源文件：`scripts/lib/pixel-athlete-motion.mjs`，游戏适配：`scripts/pixel-athlete-game.mjs`。构建同时输出 GLB、独立预览与正式 `game-renderer.js`；`index.html` 和服务器已切换到它。已清理停用的历史预览 bundle，正式游戏与独立模型预览继续使用各自当前入口。Windows 程序更新运行 `npm run build:desktop`。

`verify:pixel-athlete` 检查零错误/零警告 GLB、原身高、归一化蒙皮、九段动作每段 121 个姿态下的真实变形鞋底与膝盖方向、并步支撑/脚间距、反手手臂与躯干近似包络避让、拍杆/拍框/拍面跨线与实际变形球衣/头部的交叉，以及触球阶段向反手侧前方的拍头方向、循环与回位衔接；还实际验证离线播放、慢放、暂停、逐帧、拖动进度、桌面/手机布局及关键游戏文件 SHA-256 不变。手臂检查为骨段与躯干包络近似；球拍检查对实际蒙皮表面求交，采样拍杆、拍框和拍面跨度。仍不是任意姿态、所有网格之间的完整碰撞保证。报告在 `artifacts/pixel-athlete-*.json`。

实际模型动图可重新导出：

```powershell
npm run verify:pixel-athlete -- --motion-previews
python scripts/render-pixel-athlete-motion-gifs.py
```

导出需 Python 与 Pillow。九段单独动图位于 `artifacts/pixel-athlete-{动作英文名}.gif`；比较动图 `pixel-athlete-motion-preview.gif` 为统一节奏播放，单段动图与互动预览采用编写时的速度。

## 游戏中的适配

游戏分层取样上下身，剥离预览中的髋部横移和腾空升降，由原游戏速度和高度驱动位移，保留原身高与显示尺度。候球使用新动画自身的弓腰屈膝；横移叠加低宽站姿、交替抬脚与换向重心滞后，低球混合跨步。实时腿部 IK 按当前鞋子的实际蒙皮鞋底校正支撑，不沿用旧鞋近似尺寸。

正手、反手、跳杀与发球按原游戏 45ms 触球时刻重映射时间，并根据真实球位置求解拍面；引拍、随挥和收拍使用新轨迹。游戏触球层让球拍保持在身体前方，以适配更粗的四肢。模型的 `contact` 标记只编排视觉，不替代击球/杀球判定。较远的合法触球仍沿用原适配层的手臂延长容错，并非完整身体碰撞系统。

`node scripts/verify-browser.mjs` 检查实际候球、马步、急停、跨步鞋底、原跳跃高度和拍面定位，采样反手高球/低位防守各三种输入、六个挥拍阶段的真实变形球衣/头部与球拍避让，并回归发球、跳杀、比赛/专项及桌面/手机布局。`npm run verify:desktop` 验证开发入口和真实 Windows exe 都加载本角色。动作观感仍需用户试玩反馈；旧 Windows/Mac 分享 ZIP 是之前快照，此次未重新生成。
